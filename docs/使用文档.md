# A股超短情绪温度模型 3.2 · 使用文档

> 版本：`A-SHORT-SENTIMENT-3.2`
> 适用范围：A股超短 / 打板 / 连板生态的日频情绪状态判断
> 配套文件：`README.md`（模型原理与全部公式）、`reference_impl.py`（参考实现）、
> `model_config.json`（冻结参数）、`sample_input.csv`（输入模板）、`requirements.txt`

本文档只讲**怎么用**：怎么装、喂什么数据、得到什么、怎么读、怎么接进你自己的程序。
公式推导和权重取值理由请看同包的 `README.md`。

---

## 1. 这个模型输出什么

给它一段**按交易日排列的真实收盘数据**，它逐日算出：

| 输出 | 含义 |
|---|---|
| `S` | 市场温度，0~100 的位置值 |
| `Δ1` | 温度日变化，方向与速度 |
| `Δ2` | 温度的二阶差分，加速度/钝化/拐点 |
| 六阶段 | 修复 / 升温 / 高潮 / 降温 / 退潮 / 冰点 |
| 接缝 `J` | 分歧→一致 还是 一致→分歧 |
| 六大因子 | F 赚钱反馈、L 连板生态、R 风险质量、A 进攻扩散、B 市场广度、V 量能确认 |
| `Q` | 基础强度，最终温度的主体 |

一句话：**它不是择时模型，是"今天超短情绪处在周期哪个位置"的状态模型。**

## 3. 三分钟上手

### 3.1 用参考实现跑一条序列

```python
import pandas as pd
from reference_impl import compute_model

df = pd.read_csv("sample_input.csv", dtype={"date": str})
out = compute_model(df)

print(out[["date", "S", "delta1", "delta2", "phase", "J", "J_label"]].tail(5))
out.to_csv("model_output.csv", index=False, encoding="utf-8-sig")
```

`compute_model(df)` 接受一个 DataFrame，返回**同样行数**的 DataFrame，逐列追加
所有因子、修正项、温度和阶段。输入会自动按 `date` 升序排序。

### 3.2 取某一天的结果

```python
row = out.set_index("date").loc[pd.Timestamp("2026-09-11")]
print(row["S"], row["phase"], row["J_label"])
```

### 3.3 最小可用建议

- **至少喂 60 个交易日**，最好 250 天以上。模型的所有因子都走"同景历史百分位"，
  样本太短百分位没有意义，前几十天的数值只能当热身。
- **不要只喂一天**。模型是时间序列状态机，阶段判定需要前一日状态。
- 每日增量使用时，把历史面板存好，每天追加一行重跑，别每次都从零开始。

## 4. 输入数据：字段与口径

### 4.1 必填字段

| 字段 | 含义 | 类型 / 单位 |
|---|---|---|
| `date` | 交易日 | `YYYY-MM-DD` |
| `sh_close` | 上证指数收盘 | 点 |
| `sh_ma250` | 上证 250 日均线 | 点 |
| `tradable_count` | 正常交易股票数 | 家 |
| `advance_count` | 红盘/上涨家数 | 家 |
| `turnover` | 全市场成交额 | **单位随意，但需全程一致** |
| `limit_up` | 收盘涨停家数 | 家 |
| `limit_down` | 收盘跌停家数 | 家 |
| `first_board` | 首板家数 | 家 |
| `consecutive` | 严格连续连板家数（2板及以上） | 家 |
| `space` | 最高严格连续板高度 | 板（如 6） |
| `next_space` | 次高严格连续板高度 | 板（无则 0） |
| `bomb_rate` | 炸板率 | **0~1 小数** |
| `yday_limitup_ret` | 昨日涨停股今日反馈 | **百分点**（+4.53 填 `4.53`） |
| `yday_lianban_ret` | 昨日连板股今日反馈 | **百分点** |
| `p12` | 1进2 晋级率 | **0~1 小数** |
| `p23` | 2进3 晋级率 | **0~1 小数** |
| `p3p` | 3板以上晋级率 | **0~1 小数** |

### 4.2 可选但强烈建议的字段（龙头接缝）

| 字段 | 含义 | 单位 |
|---|---|---|
| `prev_leader_open_ret` | 昨日最高板/空间龙今日**开盘**收益率 | 百分点 |
| `prev_leader_close_ret` | 昨日最高板/空间龙今日**收盘**收益率 | 百分点 |
| `prev_leader_advance_ratio` | 昨日最高板组今日成功晋级比例 | 0~1 |

三项**同时**提供时，接缝里的"龙头承压"走完整模式；缺任意一项就自动降级成
"空间高度变化 + 高位晋级方向"的代理算法。降级不是错，只是敏感度低一些。

### 4.3 三个最容易踩的坑

**① 单位混用。** `bomb_rate`、`p12/p23/p3p` 要填小数（`0.31`，不是 `31`）；
`yday_*_ret` 要填百分点（`4.53`，不是 `0.0453`）。这两个方向相反，最容易写反。

**② 股票池必须固定。** ST、\*ST、退市整理要剔除；北交所单独处理；首板/连板/空间
全部用"严格连续涨停"，**不要**用"N天M板""反包板"凑高度。口径一换，历史百分位
就整体漂移，温度会失真。

**③ `sh_ma250` 不能用未来数据。** t 日的 MA250 只能用截至 t 日的收盘价算。
如果拿全样本算完再回填，模型就会偷看未来。

### 4.4 模板

`sample_input.csv` 给出字段顺序和格式，含可选的龙头三列（留空即降级）。
`reference_impl.py` 的 `compute_model` 不校验列名拼写，缺列会直接抛错——按模板填最稳。

## 5. 输出字段

| 列 | 说明 |
|---|---|
| `F` `L` `R` `A` `B` `V` | 六大因子，0~100 |
| `Q` | 基础强度（六因子加权） |
| `J` / `J_label` | 接缝强度与其文字标签 |
| `J_leader` `J_follower` `J_promotion` | 接缝三个分量 |
| `M` | 结构动量（四因子变化加权） |
| `S` | 最终市场温度 |
| `delta1` `delta2` | Δ1 / Δ2 |
| `phase` | 六阶段 |
| `momentum` | 动能标签 |
| `regime` | `Bull` / `Bear`（上证 vs MA250） |
| `repair_confirmed` | 是否确认修复（布尔） |
| `C_hot` `C_J` `P_breadth` `P_down` `P_bomb` `P_cool` `P_inertia` | 各项非线性修正，便于逐步核算 |

**前三行不能用**：第 1 行没有前一日状态，`delta1/delta2` 为 `NaN`；
前 20 行 `turnover_ma20` 还在热身（`min_periods=5` 起算）；
前 60 行同景样本不足，百分位会退化成全样本混合。正式使用请从第 60 行之后开始看。

## 6. 怎么读结果

### 6.1 位置：S

| S | 大致含义 |
|---:|---|
| `<35` | 极限冰点 |
| `35~45` | 深度冰点 |
| `45~55` | 冰点 |
| `55~70` | 修复 / 观察区 |
| `70~82` | 升温 |
| `82~90` | 高潮 |
| `>=90` | 强高潮 |

### 6.2 方向与加速度：Δ1 / Δ2

| 现象 | 含义 |
|---|---|
| `Δ1>0, Δ2>0` | 上攻加速 |
| `Δ1<0, Δ2>0` | 下跌收敛，可能见底 |
| `Δ1>0, Δ2<0` | 上涨钝化，注意兑现 |
| `Δ1<0, Δ2<0` | 转弱加速 |

**Δ2 比 Δ1 更早给信号。** 例如温度还在往下走（Δ1 为负），但 Δ2 已经大幅转正，
说明恶化速度在快速收敛——这是"冰点内部出现止跌苗头"，还不等于修复。

### 6.3 六阶段怎么配合看

```
修复 → 升温 → 高潮 → 降温 → 退潮 → 冰点 → 修复
```

同样的温度值，阶段不同，含义完全相反。86 分既可能是**正在升温**，也可能是
**从 95 跌下来的降温**——单看 S 分不出来，`M`（结构动量）和阶段才能分开。

### 6.4 接缝 J

| `J` | 标签 | 读法 |
|---:|---|---|
| `>= 30` | 强分歧→一致 | 分歧在收敛，情绪转强 |
| `10 ~ 30` | 弱分歧→一致 | 出现转强苗头 |
| `-10 ~ 10` | 无明显接缝 | 中性，看别的不看它 |
| `-30 ~ -10` | 一致→分歧 | 一致性在瓦解 |
| `<= -30` | 强一致→分歧 | 高位开始崩，最需要警惕 |

**J 只修正温度 ±1.5 分**，它真正的价值是**标签**：帮你更早识别周期切换。
不要指望 J 大幅拉动 S。

### 6.5 一个真实例子

2026-09-11（数据来自真实收盘面板）：

```
市场温度 S: 43.4
Δ1: -0.5          # 还在跌，但几乎停住
Δ2: +20.8         # 恶化速度大幅收敛
六阶段: 冰点
接缝J: +14.6（弱分歧→一致）
赚钱反馈F: 60.3    # 昨日强势股反馈已转正
市场广度B: 11.6    # 但全市场只有 11.6% 红盘
状态: 深度冰点｜下跌收敛/退潮衰竭
```

正确读法：**还没有脱离冰点，但内部已经出现止跌信号。**
不能因为昨日反馈翻正就直接宣布"修复"——21 家跌停、红盘率 11.6% 还摆在那里。
这正是模型把 `B` 和"修复确认"条件单独拎出来的原因。

## 7. 进阶：EmotionEngine 五个接口

参考实现是**批处理**的（喂一段历史，出整条序列）。如果要接进自己的选股/复盘系统，
用封装好的 `EmotionEngine`（在 `股票分析` 项目里）：

```python
from emotion import EmotionEngine

engine = EmotionEngine().load_csv("你的面板.csv")

engine.calculate_temperature("2026-09-11")   # 43.4
engine.calculate_J("2026-09-11")             # {'value': 14.55, 'label': '弱分歧→一致', ...}
engine.detect_cycle("2026-09-11")            # {'phase': '冰点', 'grade': '深度冰点', ...}
engine.get_market_state("2026-09-11")        # 完整快照：全部因子 + 修正项 + 牛熊 + 接缝
engine.adjust_stock_score(72.0, {"high_relay": 1.0}, day="2026-09-11")
print(engine.render("2026-09-11"))           # 每日状态文本
```

`day` 省略时取面板最后一天。引擎内部缓存整条序列，重复调用不重算。

## 8. 接缝修正 → 个股评分环境权重

这是"把市场状态变成个股评分前的一道乘数"的扩展层，**不属于 3.2 核心公式**，
参数单独放在 `environment_weights.json`，与 `model_config.json` 隔离。

七种风格标签：`leader`（龙头/空间龙头）、`high_relay`（高位接力/连板追涨）、
`low_first`（低位首板）、`theme`（题材强度）、`oversold`（超跌修复）、
`defensive`（防守/低波动）、`ice_repair`（冰点修复候选）。

六阶段的乘数（节选）：

| 阶段 | leader | high_relay | low_first | oversold | defensive |
|---|---:|---:|---:|---:|---:|
| 高潮 | 1.18 | 1.05 | 0.95 | 0.85 | 0.85 |
| 升温 | 1.12 | 1.05 | 1.00 | 0.92 | 0.92 |
| 修复 | 1.05 | 0.95 | 1.10 | 1.10 | 1.00 |
| 降温 | 0.98 | 0.85 | 1.05 | 1.05 | 1.05 |
| 退潮 | 0.90 | 0.72 | 1.12 | 1.15 | 1.15 |
| 冰点 | 0.88 | 0.68 | 1.08 | 1.12 | 1.18 |

四条约束，避免环境判断喧宾夺主：

1. 多风格按权重做**几何混合**，同一只票不会被重复加成；
2. 接缝 J 额外给 `±0.08` 倾斜（J 越正越偏向龙头/接力/题材）；
3. 冰点阶段只有同时满足 `S<=55`、`J>=10`、晋级方向改善、龙头未承压，
   才把 `ice_repair` 提到 `1.25` 倍；
4. 总乘数**限幅在 `[0.7, 1.3]`**——环境能改变排序，不能主导评分。

实跑对比（同一只 72 分的票，2026-09-11 冰点｜弱分歧→一致）：

| 情形 | 乘数 | 调整后 |
|---|---:|---:|
| 低位首板 + 超跌修复 | 1.093 | **78.7** |
| 冰点修复候选（条件全中） | 1.300 | **93.6** |
| 高位接力 | 0.706 | **50.9** |

同一个环境里，做低位修复比做高位接力高出约 28 分。这就是"环境因子"要表达的东西。

## 9. 接入自己项目的两种方式

**方式 A：只要公式（最轻）**

把 `reference_impl.py` 和 `model_config.json` 拷过去，直接
`from reference_impl import compute_model`。零依赖（除 pandas/numpy）、无状态，
适合批处理、回测、跑历史。

**方式 B：要引擎（推荐）**

把整个 `emotion/` 包 + `config/` 拷过去，用 `EmotionEngine`。多出的是：
标量化接口、温度等级标签、每日状态文本、以及环境权重调整。
`emotion/core.py` 与 `reference_impl.py` 逐行一致，行为完全相同——
有测试锁着（405 天真实面板、全部 22 个数值列最大绝对差 `0.0`）。

两种方式都可以，看你要不要那层封装。

## 10. 常见问题

**Q：为什么涨得很猛的那天，阶段给的是"修复"而不是"高潮"？**
A：状态机是**按顺序**判定的，`repair_confirmed` 成立就直接返回"修复"，优先级高于
"高潮"。所以从冰点/退潮次日出现强反弹时（例如真实面板 2026-09-07，S=90.1，J=+54.5），
标签是"修复"而不是"高潮"。这是参考实现的既有行为，不是 bug。
若要"高温优先判高潮"，需要改状态机顺序并重做回测。

**Q：温度怎么和我自己算的差几个点？**
A：先查三件事——股票池是否一致、`bomb_rate`/`p12` 是不是填了小数、
`yday_*_ret` 是不是填了百分点。这三项不同，差 5~10 分很正常。

**Q：只有一两个月数据能跑吗？**
A：能跑，但同景样本不足会退化成全样本混合，百分位参考价值有限。
建议 250 个交易日以上。

**Q：1进2 / 2进3 某天分母很小怎么办？**
A：分母 <3 时该板位的晋级率噪声极大。README 第 17 节建议降低该项权重或沿用前值，
不要当成有效信号。

**Q：模型能直接给买卖建议吗？**
A：不能。它给的是**市场状态**，不是个股信号。要落到交易，还需要叠加个股逻辑和
你的风控。本模型用于市场状态研究，不构成投资建议。

**Q：改了公式怎么确认没改坏？**
A：留一份原始 `reference_impl.py`，改完后拿同一段真实面板跑两边，逐列比对。
`股票分析` 项目里已经把这件事做成了测试：

```bash
python -m pytest tests -q        # 含 405 天逐列口径比对
```
